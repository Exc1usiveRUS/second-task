
## Пояснения по SOLID

### Single Responsibility Principle

В "легаси" коде метод processOrder() держал в себе всю логику по расчету скидки и комиссии заказа,
валидации и формирования чека. Теперь эта логика вынесена в отдельные классы. Оставил список заказов
внутри OrderService, так как реализация подразумевает хранение заказов в памяти.

### Open/Closed Principe

В исходном коде добавление новой логики подразумевало изменение кода через добавление новых if-else ветвлений.
Теперь новый вид комиссии, скидки или печати - новый обработчик без изменений вызывающего кода.

### Liskov Substitution Principle

Честно говоря, не знаю что сюда можно написать, так как в исходном коде вообще не было абстракций и логики наследования.

### ISP — Interface Segregation Principle

Опять же, отсутствие абстракций как таковых. Выделил несколько узконаправленных интерфейсов для точечного добавления
логики без необходимости реализовывать ненужные методы.

### Dependency Inversion Principle

Исходный класс знал все формулы и детали реализации. Теперь класс полностью зависит от абстракций и предоставляет
необходимую реализацию в зависимости от поступающих данных.
